Necesito construir una aplicación web progresiva (PWA) de finanzas personales llamada PerJaus, con las siguientes características y requisitos técnicos:

## Stack técnico
- React + TypeScript + Vite
- Tailwind CSS con shadcn/ui para componentes
- Supabase como backend (base de datos PostgreSQL, autenticación, Realtime)
- Phosphor Icons + Lucide para iconografía
- Despliegue en Netlify (auto-deploy desde rama main)
- Integración con bot de Telegram (@PerJausBot)
- Google OAuth para inicio de sesión

## Funcionalidades

### 1. Autenticación con Google OAuth
- Landing page con botón "Iniciar sesión con Google"
- Usar Supabase Auth con proveedor Google
- El redirect después del login debe ser dinámico: usar `${window.location.origin}/auth/callback` para que funcione tanto en localhost como en producción
- Configurar Supabase Auth:
  - `site_url`: `http://localhost:5173` (para desarrollo local)
  - `uri_allow_list`: incluir `https://perjaus.netlify.app/auth/callback` y `http://localhost:5173/auth/callback`
- Manejar sesión con AuthContext + useAuth hook
- Botón "Cerrar sesión" en el menú de configuración

### 2. Dashboard principal
- Header con nombre "PerJaus", email del usuario, botones +Gasto, +Ingreso, y engranaje de configuración
- 3 tarjetas de resumen: Balance del mes, Top categoría, Transacciones
- Tabs: Resumen, Gastos, Ingresos
- En la pestaña Resumen:
  - DonutChart: distribución de gastos por categoría
  - BarChart: evolución mensual de gastos (últimos 6 meses)
  - BudgetProgress: presupuesto vs real con Progress bars

### 3. Registro de gastos e ingresos
- AddExpenseDialog: formulario con monto, concepto, categoría (dropdown dinámico desde categorías del usuario), fecha
- AddIncomeDialog: formulario con monto, concepto, fecha (categoría fija "Ingresos")
- ExpenseList: tabla paginada con filtros por categoría y rango de fechas, botón eliminar
- IncomeList: tabla paginada con filtros, botón eliminar
- Después de guardar o eliminar, los datos deben actualizarse inmediatamente en el dashboard (usar refetch callbacks + Supabase Realtime)

### 4. Presupuestos mensuales
- BudgetSettings: diálogo que lista todas las categorías de gasto con input de monto
- Al guardar, upsert en tabla `presupuestos` y refetch instantáneo en el Dashboard
- BudgetProgress en dashboard: muestra barra de progreso (gastado / presupuesto) con color por categoría
- Cuando se elimina una categoría con presupuesto = $0, el presupuesto también se elimina automáticamente

### 5. Categorías personalizadas (sistema completo)
- Tabla `categorias` en Supabase con columnas: id, user_id, nombre, color, icono, created_at
- Restricción UNIQUE(user_id, nombre)
- Row Level Security habilitado (usuarios solo ven/editan sus propias categorías)
- Categorías predefinidas (no editables ni eliminables): Alimentación, Transporte, Vivienda, Salud, Entretenimiento, Ingresos, Otros
- Cada categoría predefinida tiene un color fijo en CATEGORIA_COLORS
- Las categorías personalizadas se almacenan en la tabla `categorias` y se cargan con el hook useCategorias
- CategoryEditor: diálogo principal que lista todas las categorías con:
  - Círculo con icono + color de fondo
  - Nombre de la categoría
  - Para predefinidas: candado (locked)
  - Para personalizadas: ColorPicker inline (12 colores), IconPicker inline (25 iconos Phosphor), botón eliminar
- El botón "Agregar categoría" abre un diálogo separado (no inline) con campos: Nombre, ColorPicker, IconPicker, y botones Cancelar/Agregar
- Al agregar, el popup se cierra inmediatamente y la categoría aparece en la lista con todos sus controles (círculo + icono + nombre + ColorPicker + IconPicker + eliminar)
- deleteCategoria con protección de 3 niveles:
  1. Si la categoría tiene gastos asociados → bloquear con mensaje "Hay X gasto(s) con esta categoría. Elimínalos primero."
  2. Si tiene presupuesto con monto > $0 → bloquear con mensaje "El presupuesto es $X. Ponlo en $0 primero."
  3. Si tiene presupuesto con monto = $0 → eliminar el presupuesto automáticamente
  4. Luego eliminar la categoría y refrescar la lista

### 6. Menú de configuración (SettingsPopup)
- Diálogo que se abre al hacer clic en el engranaje
- 4 botones grandes tipo card: Presupuesto, Categorías, Gasto, Ingreso
- Cada botón abre su respectivo diálogo al hacer clic
- Botón "Cerrar sesión" al final en rojo
- Patrón "closeAnd(fn)": cierra el popup y después de 150ms abre el diálogo destino

### 7. Integración Telegram (@PerJausBot)
- Vincular chat de Telegram con cuenta web mediante código
- Comandos del bot:
  - /gasto Categoria monto concepto
  - /ingreso monto concepto
  - /presupuesto Categoria monto
  - /resumen: gastos del mes
- Edge Function `telegram-webhook` en Supabase

### 8. Sincronización en tiempo real (Supabase Realtime)
- Habilitar Realtime para las tablas: `gastos`, `presupuestos`, `categorias`, `ingresos`
- Cada hook (useGastos, useIngresos, usePresupuestos, useCategorias) debe tener un canal Realtime con nombre único
- Los canales deben escuchar `postgres_changes` con event = "*" para capturar inserts, updates y deletes
- Después de operaciones de guardado/eliminación, llamar refetch explícito además de Realtime (cinturón + suspensores)

### 9. PWA (Progressive Web App)
- Manifest con: nombre "PerJaus", lang "es", display "standalone", orientation "portrait-primary"
- Iconos: pwa-192x192.png y pwa-512x512.png (con purpose "any maskable")
- Service Worker con autoUpdate via vite-plugin-pwa
- Tema: dark mode con color primario #FFD600 (amarillo)

### 10. Diseño UI/UX
- Tema oscuro (zinc-950 fondo, zinc-800 bordes, zinc-100 texto)
- Colores ácidos neón: amarillo (#FFD600) como acento principal
- Gradiente radial sutil en el fondo
- Efectos hover en botones y cards
- Formateo de moneda en CLP (peso chileno) sin decimales
- Fechas en formato local español

### 11. Base de datos (Supabase)
- Tabla `gastos`: id (UUID), monto (NUMERIC), concepto (TEXT), categoria (TEXT, sin CHECK constraint), fecha (TIMESTAMPTZ), user_id (FK → auth.users), created_at
- Tabla `ingresos`: misma estructura que gastos
- Tabla `presupuestos`: id, user_id, categoria, mes (YYYY-MM-DD), monto, created_at, updated_at
- Tabla `categorias`: id, user_id, nombre (UNIQUE con user_id), color, icono, created_at
- Tabla `user_telegram_links`: id, user_id, telegram_chat_id, created_at
- RLS habilitado en todas las tablas con políticas por user_id
- Índices en columnas de búsqueda frecuente (fecha, categoria, user_id)

### 12. Configuración de despliegue
- netlify.toml: build command "npm run build", publish directory "dist", redirects "/* → /index.html" (SPA)
- En el dashboard de Netlify, configurar variables de entorno: VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY
- Auto-deploy desde rama main

### 13. Supabase Auth settings (crítico para producción)
- site_url: http://localhost:5173
- uri_allow_list: https://perjaus.netlify.app,https://perjaus.netlify.app/auth/callback,http://localhost:5173,http://localhost:5174,http://localhost:3000

### 14. Manejo de errores
- ErrorBoundary componente clase que captura errores de React y muestra mensaje
- Mensajes de error visibles en diálogos (rojo, con fondo semitransparente)
- console.error para errores de autenticación

### 15. Convenciones de código
- Sin comentarios en el código
- Convenciones de shadcn/ui para componentes
- Alias @/ para imports desde src/
- TypeScript estricto
- Sin emojis en el código (a menos que el usuario los solicite explícitamente)
